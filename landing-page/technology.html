状态追踪

6种世界状态追踪维度

每集生成后自动分析剧本内容，提取6种维度的状态变化并更新到世界状态快照中。

⚔

装备变化

追踪角色获得和失去的装备，累计计算当前持有装备列表。

⚡

能力变化

记录角色新展示的能力，累计维护当前能力清单。

💧

身体状态

追踪受伤、痊愈等身体状况变化，影响后续剧情约束。

🧠

精神状态

记录角色心理变化，确保情感表现与经历一致。

👊

战力状态

追踪战斗力变化，防止实力忽高忽低的穿帮问题。

🔴

永久性标记

记录伤疤、残疾、觉醒等不可逆变化，永久影响角色描写。

时间衰减

世界状态快照链时间衰减

类似游戏存档机制，每集生成后创建完整世界状态快照。越近的集数权重越高，越远的集数权重越低，模拟人类"近期记忆更清晰"的特点。

📊

快照内容

每个快照包含：角色状态Map、伏笔列表、剧情状态、世界设定、约束追踪，完整记录该集结束时的世界全貌。

🔗

链式继承

生成第N集时，复制第N-1集的WorldState作为基础，应用本集分析结果后保存为新快照，形成完整的状态链。

🧠

智能衰减

近期事件保持完整细节（100%权重），远期事件只保留关键信息（20%权重），平衡上下文长度与信息完整性。

👥

characterCards 前作角色卡

自动加载前季所有角色的完整档案，包括金字塔层级、关系图谱和最终状态，确保续季角色行为与前作一致。

📋

finalState 前作结局状态

提取前季最后一集的世界状态快照，包括势力格局、地点发现、关键道具归属等，作为续季的世界观起点。

🌱

unresolvedPlots 未回收伏笔

收集前季标记为 dormant 或 planted 状态的伏笔列表，续季大纲生成时自动融入，确保前作留下的"坑"在续季中得到回收。

质量验证

9种验证问题类型 × 3级严重度

ScriptValidator 通过滑动窗口（10集窗口、5集步长、50%重叠）逐段扫描剧本，检测9种问题类型并按严重度分级。

🔴

Critical 严重问题（每个扣1.5分）

logic逻辑漏洞：剧情逻辑不通
character角色矛盾：行为前后矛盾
timeline时间线错误：时间顺序混乱
unresolved悬念未收：挖的坑没填
🟠

Warning 一般问题（每个扣0.5分）

setting设定冲突：世界设定前后不一致
continuity剧情不连贯：剧情衔接不顺
relationship关系问题：角色关系处理不当
🔵

Suggestion 建议改进（每个扣0.1分）

pacing节奏问题：节奏太快或太慢
dialogue对话问题：对话不够自然

工程韧性

多重容错保障机制

从API调用到数据存储，每个环节都有容错和恢复机制。

🔄

API Key 轮转

3个API Key循环使用，单Key限流时自动切换，最大化吞吐量。

🔁

指数退避重试

遇到429/500错误时自动重试，最多5次，间隔指数递增避免雪崩。

📈

max_tokens 降级

当token超限时自动降级max_tokens参数，确保生成不中断。

💾

断点续传

批量任务状态实时持久化，中断后从断点无缝恢复，不重复生成。

🔒

事务级回滚

跨集修复操作支持事务级回滚，修复失败时自动恢复原始数据。

降级策略

三级回退保障

当核心模块异常时，系统自动降级到备用方案，确保生成流程不中断。

🧠

AI约束降级

AI约束决策失败时，自动回退到规则引擎生成基础约束，保证每集都有约束指导。

👀

多头分析降级

注意力头分析失败时，跳过失败头并使用基础上下文继续生成，不阻塞主流程。

💡

梗概优化降级

EpisodePlanEnhancer 优化失败时，直接使用原始梗概进行生成，确保流程不中断。

6种任务状态

pending（等待）→ running（执行中）→ paused（已暂停）→ completed（已完成）/ failed（失败）/ stopped（已停止）。失败任务可人工处理后恢复。

🔄

自动恢复机制

服务重启时自动检测未完成任务并恢复执行。任务状态实时持久化到数据库，确保断电、崩溃等异常情况下不丢失进度。

📡

实时状态广播

TaskManagerController 维护 SSE 连接池，实时广播任务状态变化和生成日志，前端通过 /api/tasks/stream 接收。

重试机制

AIClient 指数退避重试

智能重试策略区分普通错误和速率限制，指数递增延迟避免雪崩效应。

5

🔁

普通错误退避

2秒 → 4秒 → 8秒，每次翻倍递增。适用于临时性网络错误和服务端异常。

🕑

速率限制退避

30秒 → 60秒 → 120秒，AI服务繁忙时等待更久。适用于 429 Too Many Requests 错误。

重试对照

各组件重试策略对照

不同组件采用不同的重试策略和回退方案，确保每个环节都有容错保障。

🤖

AIClient 网络重试

最多5次，指数退避（2s→4s→8s→16s→30s）。处理 ECONNRESET、ETIMEDOUT、429、529 等网络和服务端错误。

📝

剧本生成重试

最多2次，立即重试，使用改写模式。约束验证未通过时，强化未满足约束后改写重试。

📄

JSON解析重试

最多3次，立即重试，智能修复后重试。AI返回的JSON格式异常时，自动尝试修复并重新解析。

🧠

AI约束决策重试

最多3次，线性退避（1s×尝试次数）。全部失败后回退到规则引擎生成基础约束。
