使用流程

8步完成剧本创作

从项目创建到成品输出，全流程自动化，简单高效。

1

创建项目

设定项目名称、选择题材类型（24种预设题材），配置故事模式（完整剧/可续集/承接季）、集数、每集字数等基本参数。

24种题材预设各自配备专属注意力头组合和节奏参数。3种故事模式决定大纲生成策略、结局处理方式和伏笔管理规则。项目创建时自动初始化 WorldStateManager 和 CharacterLifecycleManager。
2

编写/生成大纲

输入故事梗概，AI通过五层渐进式生成流程自动扩展：故事内核 → 角色功能 → 角色卡片 → 情节大纲 → 分集摘要，也可手动编写或调整。

五层渐进式生成确保故事结构完整：第1层提炼故事内核与主题，第2层规划角色功能定位，第3层生成详细角色卡片，第4层编排情节大纲与冲突节点，第5层细化为分集摘要。每层输出作为下一层的输入上下文。
3

生成角色档案

AI根据大纲自动生成角色档案，角色金字塔5级模型自动分级（核心/常驻/弧线/临时/龙套），构建关系图谱与量化追踪。

CharacterLifecycleManager 自动为角色分配金字塔层级，分级上下文预算（核心800/常驻500/弧线300/临时150/龙套50字符）。7级关系量化追踪，6种事件类型驱动关系动态变化。
4

选择输出格式

从15种预设格式中选择：标准动态漫、条漫、小说体、影视剧本、广播剧、游戏脚本、短视频、日式漫画、舞台剧、互动剧、真人短剧、AI数字人、美漫、国漫、纪录片。

每种格式定义独立的输出模板和结构规范。格式选择影响 BudgetAllocator 的预留空间分配和 RhythmControl 的节奏参数。格式间可一键切换，无需重新生成。
5

启动批量生成

一键启动批量生成引擎，API Key 3轮轮转避免限流，5次指数退避重试，max_tokens自动降级策略确保100+集稳定完成。

BatchGenerator 调度引擎自动管理生成队列。API Key轮转（3个Key循环使用），遇到429/500错误时指数退避重试（最多5次）。当token超限时自动降级 max_tokens 参数。断点续传机制支持中断后无缝恢复。
6

实时监控进度

12种SSE消息类型实时推送生成进度，可随时查看每集状态、字数统计、质量评分和世界状态快照。

SSE（Server-Sent Events）支持12种消息类型：生成开始/进度/完成/失败/重试/跳过/暂停/恢复/取消/统计/质量/状态。前端通过 EventSource 实时接收并渲染进度面板。
7

审核与改写

对生成结果进行审核，跨集联动修复（6个API端点、事务级回滚），AI置信度评分驱动级联改写，自动适配上下文。

CrossEpisodeRepairService 提供6个API端点协同联动。修改某集后自动分析影响范围，AI置信度评分决定是否级联修复。BatchCoherentRewriteService 实现连贯上下文滚动传递，事务级回滚保障数据安全。
8

导出成品

15种格式一键切换导出最终剧本，支持批量导出和自定义排版，多格式无需重新生成即可转换。

格式转换服务基于模板引擎实现，已生成的剧本内容可在15种格式间自由切换。批量导出支持按项目、按集数范围筛选，自定义排版参数控制输出样式。

改写体系

四级改写覆盖全场景

从单集微调到批量连贯改写，4种改写类型满足不同编辑需求。

✍

单集改写

支持全文改写和选区改写两种模式。选区改写精准定位修改范围，全文改写重新生成整集内容，均自动继承上下文状态。

⚡

AI智能改写

一键智能优化，AI自动分析当前剧本的薄弱环节并针对性改写，无需手动指定修改方向。

🔗

多集协调改写

选择多集范围统一生成改写方案，AI一次性输出所有集的修改内容，再自动解析并保存到各集，确保跨集一致性。

🛠

批量连贯改写

先生成整体改写计划，再逐集执行。连贯上下文滚动传递，每集改写结果作为下一集的输入上下文，保持前后一致。

🔴

Critical 约束

任何一条未满足即强制重试。涉及角色核心设定、关键剧情走向等不可妥协的硬性要求。

🟠

Important 约束

满足率低于50%时建议重试。涉及节奏控制、伏笔回收等影响质量的重要要求。

🔵

Normal 约束

约束数量≥3个且满足率低于30%时建议重试。涉及风格微调、细节优化等扩展头产生的建议性约束。

跨集修复

5种跨集问题智能修复

6个API端点协同工作，AI分析问题影响范围，生成修复方案，事务级回滚保障数据安全。

🔍

悬念未收 unresolved

伏笔埋设后超期未回收。例如第5集埋的伏笔到第25集还没回收，需要在多集中铺垫和回收。

👤

角色矛盾 character

角色在不同集数的性格表现矛盾。例如第10集和第20集的角色行为不一致，需要协调多集表现。

🕑

时间线错误 timeline

时间描述前后不一致。例如第15集说"三天后"，但第16集变成了"一周后"，需要修正多集时间。

🌎

设定冲突 setting

世界观设定前后矛盾。例如第8集说主角不会飞，第18集却飞了，需要在多集中保持设定一致。

🔗

剧情不连贯 continuity

相邻集数衔接不上。例如第12集结尾和第13集开头对不上，需要同时修改相邻集数。

回滚机制

3种回滚类型保障数据安全

修复操作支持多种粒度的回滚，确保任何修改都可以安全撤回。

🔄

完整回滚

恢复所有涉及集数到修复前的状态。适用于修复效果整体不满意，需要全部撤回的场景。

✍

部分回滚

只恢复指定集数，保留效果好的修改。适用于某些集修复效果好、某些不好的场景。

⚡

30秒一键撤销

应用修复后30秒内显示撤销按钮，一键撤销刚才的操作。适用于刚应用就发现问题的场景。

大纲模式

基础3步 vs 增强5步

两种大纲生成模式适配不同需求，增强模式新增故事内核提炼和角色功能设计两个前置步骤。

📚 基础模式（3步）

  • ✓ 人物卡生成
  • ✓ 剧情大纲
  • ✓ 分集梗概
  • ✓ 向后兼容，不传新参数即启用
  • ✓ 适合轻量项目和简单场景
VS

⚡ 增强模式（5步）

  • ✓ 故事内核提炼（卖点/情绪/结构/冲突）
  • ✓ 角色功能设计（主角/对手/助力者矩阵）
  • ✓ 人物卡生成（基于内核和功能）
  • ✓ 剧情大纲
  • ✓ 分集梗概（每批20集）
叙事节奏

3种叙事节奏风格

Pacing Style 控制大纲生成时的整体节奏密度，适配不同平台的内容消费习惯。

⚡

fast 快节奏

10秒必出爆点，每集2-3个爽点。适合竖屏短剧，观众注意力短，需要密集刺激。

▶

standard 标准

正常铺垫节奏，每集1-2个爽点。适合横屏短剧，有适当的铺垫和发展空间。

🌱

slow 慢节奏

细腻展开叙事，3-5集世界观建设。适合长篇网剧，注重氛围营造和角色塑造。
