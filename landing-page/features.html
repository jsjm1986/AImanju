三大技术突破

不是简单的AI文本生成，而是一套完整的剧本工程系统。

AI约束决策引擎

不是硬编码规则，AI理解剧情语义后自主做出约束决策。每个约束包含主体、对象、方法论和验证标准，由同一AI调用共同生成，确保约束与剧情深度耦合。

结构化约束：subject / object / methodology[] / validationCriteria[]，约束与验证标准由同一AI调用共同生成
👀

多头注意力分析

借鉴Transformer架构，23种注意力头类型（4种基础必选 + 19种扩展）通过 Promise.all 并行执行，按剧集类型动态调整权重，全方位保障剧本质量。

基础头：角色一致性 / 剧情连续性 / 伏笔追踪 / 世界观一致性，扩展头按题材动态启用
🌱

伏笔生命周期管理

完整的伏笔状态机：planted（埋设）→ dormant（休眠）→ awakened（唤醒）→ resolved（回收）/ abandoned（放弃）/ merged（合并）。5种伏笔分类，4种数据类型（suspense/character/item/plot），超期自动预警（高优先级:10集、普通:20集、低:30集）。

6种状态流转：planted → dormant → awakened → resolved / abandoned / merged，休眠伏笔可被后续剧情唤醒重新激活
伏笔分类

5种伏笔智能分类

AI自动识别伏笔类型，不同类型采用不同处理策略，避免"所有伏笔都必须回收"的机械处理。

🌱

真正伏笔 true_foreshadowing

真正的"坑"，必须在规定集数内回收。高优先级10集内、普通20集内、低优先级30集内必须填坑，超期5/10/15集自动预警。

🌈

氛围描写 atmosphere

只是渲染气氛的描写，不需要回收。例如"远处传来诡异的笛声"——营造氛围即可，不必解释笛声来源。

📚

背景铺垫 setup

世界观或背景设定的铺垫，可选回收。例如"这座城市有千年历史"——可以展开也可以不展开。

🔥

悬念钩子 hook

吸引观众继续追看的钩子，承接即可。例如集末"门外传来脚步声"——下集开头接上就行。

🔄

重复伏笔 redundant

与已有伏笔重复的内容，自动合并处理。避免同一个线索被重复埋设，保持伏笔清单的整洁。

约束结构

结构化约束字段设计

每个约束不只是"需要打脸"这种抽象描述，AI会同时生成"怎么做"和"怎么验证"，确保生成与验证标准一致。

👤

subject 执行者

指明谁来执行约束。例如"主角"——明确约束的执行主体，避免模糊指代。

🎯

object 对象

指明对谁执行。例如"反派张三"——明确约束的作用对象，让AI知道具体针对谁。

📝

methodology[] 实现方法

给生成AI的具体建议列表。例如["让对手先嘲讽", "主角反击", "对手震惊"]——提供写作思路。

✅

validationCriteria[] 验证标准

给验证AI的检查项列表。例如["必须有嘲讽对话", "必须有反击描写"]——提供评分标准，与methodology由同一AI同时生成。

📚

约束验证重试

ConstraintValidator 自动验证生成内容是否满足约束任务清单。3级严重性分层判断：Critical未满足强制重试、Important满足率低于50%建议重试、Normal约束≥3个且满足率低于30%建议重试。最多2次改写模式重试。

  • ✓ Critical（基础头）：未满足强制重试
  • ✓ Important（多头共识≥2）：满足率<50%建议重试
  • ✓ Normal（扩展头）：≥3个且满足率<30%建议重试
  • ✓ AI逐条验证并给出证据和置信度
  • ✓ 未满足约束自动强化后改写重试，最多2次
